## 1. 專案目標

在出發地張貼 QR code，使用者掃碼後看到任務內容與店家位置，導航到店面，到店後在任務頁上兌換禮物。

第一階段只做出可運作的任務流程，不蒐集任何資料。

## 2. 階段劃分與範圍

| 階段 | 內容 | 狀態 |
|---|---|---|
| 第一階段 | 單一靜態網頁：定位確認、任務內容、店家地圖、導航、兌換 | 本文件第 3 至 10 節 |
| 第二階段 | 後端記錄、身分識別、LINE 整合 | 暫不規劃，方向記錄於第 11 節 |

**第一階段包含**

- 一張 QR code、一個出發地、一個目的地（店面）。
- 一個靜態任務頁，以手機瀏覽器開啟。
- 開始任務時以 GPS 確認使用者在目的地方圓指定公里內（預設 5 公里），通過才顯示任務。
- 任務內容、店家地圖圖片、Google Maps 導航連結。
- 兌換按鈕與已兌換畫面。

**第一階段不包含（已確認的決定）**

| 項目 | 決定 | 影響 |
|---|---|---|
| 後端與資料庫 | 不做 | 所有邏輯在使用者手機的瀏覽器內執行 |
| 登入與身分識別 | 不做 | 不知道使用者是誰 |
| 掃碼、導航、兌換的記錄 | 暫不記錄 | 沒有任何統計數據 |
| 防止重複兌換 | 不防範 | 清除瀏覽器資料即可重新兌換，由店員把關 |
| 確認是否由 QR code 進入 | 不確認 | 視為知道網址的人都是掃碼而來 |
| 到店時的位置檢查 | 不做 | 由店員確認客人到場 |

## 3. 系統架構

```
[出發地 QR code]        [店內 QR code]（同一張）
      │ 掃描                  │ 到店後掃描
      v                       v
[手機瀏覽器：任務頁] ──開始導航──> Google Maps
      │
      ├─ 瀏覽器定位功能（取得 GPS，在手機上計算距離）
      └─ 瀏覽器儲存空間（記住任務狀態）

[靜態網站空間]（只負責提供網頁檔案）
```

| 元件 | 職責 |
|---|---|
| QR code | 印刷品，內容為任務頁網址。出發地與店內各貼一張，內容相同。 |
| 任務頁 | 靜態網頁。取得定位、判斷範圍、顯示任務、開啟導航、處理兌換。 |
| 瀏覽器儲存空間 | 在這支手機上記住「任務已開始」與「已兌換」。 |
| 靜態網站空間 | 提供網頁檔案，必須支援 HTTPS。 |

沒有伺服器端程式，沒有資料離開使用者的手機。

## 4. 使用者流程

### 4.1 主要流程

1. 使用者在出發地用手機掃 QR code，瀏覽器開啟任務頁。
2. 任務頁讀取這支手機的任務狀態：
   - 已兌換 → 顯示「已兌換」畫面。
   - 任務已開始 → 跳到步驟 5。
   - 沒有狀態 → 繼續步驟 3。
3. 任務頁說明需要確認位置，使用者按下「確認我的位置」後，瀏覽器詢問定位權限。
4. 任務頁取得座標，在手機上計算與目的地的距離：
   - 在允許範圍內 → 在瀏覽器儲存空間記下「任務已開始」，進入步驟 5。
   - 超出範圍 → 顯示「不在範圍」畫面，可重試。
   - 拒絕定位或定位失敗 → 顯示開啟權限的說明，可重試。
5. 任務頁顯示任務內容、店家地圖圖片、店名與地址、「開始導航」與「兌換」按鈕。
6. 使用者點「開始導航」，Google Maps 開始導航到店面。
7. 使用者到店，切回任務頁，或掃店內的 QR code 重新開啟。因為手機上已有「任務已開始」的狀態，不會再檢查定位。
8. 店員點「兌換」，跳出確認視窗，確認後在瀏覽器儲存空間記下兌換時間。
9. 畫面變成「任務成功／已兌換」，顯示兌換時間與跳動的時鐘。

### 4.2 畫面狀態

| 狀態 | 顯示內容 | 進入條件 |
|---|---|---|
| 確認位置 | 活動說明、三個步驟預告、「確認我的位置」按鈕 | 手機上沒有任務狀態 |
| 不在範圍 | 原因說明、活動地點、重試按鈕 | 距離超出允許範圍 |
| 定位失敗 | 開啟定位權限的步驟、重試按鈕（沿用「不在範圍」版型） | 拒絕權限或逾時 |
| 任務進行中 | 任務內容、店家地圖、「開始導航」、「兌換」 | 已通過定位 |
| 兌換確認 | 確認視窗 | 點了「兌換」 |
| 已兌換 | 任務成功、兌換時間、跳動時鐘 | 已確認兌換 |
| 活動未開始／已結束 | 活動期間說明 | 目前時間在活動期間外 |

## 5. 功能設計

### 5.1 定位與範圍判斷

- 使用瀏覽器標準的 Geolocation API，要求高精確度，逾時設為 10 秒。
- 由使用者按下按鈕後才觸發，不在頁面載入時直接跳出權限視窗。
- 取得座標後，在網頁內以 Haversine 公式計算與目的地的直線距離。
- 距離小於或等於允許半徑即通過。允許半徑由環境設定 `NAV_RADIUS_KM` 決定，預設 5 公里（見 5.5）。
- 瀏覽器回報的誤差值超過 1 公里時視為不可靠，請使用者重試。
- 座標只用於當下計算，不儲存、不傳送。

範圍的圓心是目的地：目前只有目的地座標，沒有另外設定出發地。QR code 張貼的出發地只要在這個範圍內，使用者就能通過。「不在範圍」畫面會顯示使用者目前距離目的地多遠。

### 5.2 任務狀態

存放在瀏覽器的 `localStorage`，單一鍵值：

| 鍵 | 內容 |
|---|---|
| `navquest.state` | `{ "startedAt": "<時間>", "redeemedAt": "<時間或 null>" }` |

- 沒有這筆資料：尚未開始，顯示「確認位置」。
- 有 `startedAt`、沒有 `redeemedAt`：任務進行中。
- 有 `redeemedAt`：已兌換。

讀寫 `localStorage` 可能失敗（例如無痕模式或儲存空間被停用），程式需要處理例外：失敗時任務仍可在當次瀏覽中進行，但重新開啟後要重新定位。

### 5.3 導航

「開始導航」是一般連結，使用 Google Maps 官方的通用網址格式：

```
https://www.google.com/maps/dir/?api=1&destination=<緯度>,<經度>&destination_place_id=<Place ID>
```

- 不指定起點，由 Google Maps 使用使用者目前位置。
- 帶 `destination_place_id` 讓目的地顯示店名。
- 手機有安裝 Google Maps 時會開啟 App，否則開啟網頁版。

### 5.4 兌換

- 「兌換」按鈕旁註明「請交由店員操作，自行點擊視同已兌換」。
- 點擊後先顯示確認視窗，確認後寫入 `redeemedAt`。
- 已兌換畫面顯示兌換時間與每秒跳動的現在時間，讓店員分辨真實頁面與截圖。

### 5.5 設定值

可隨時調整的參數放在環境設定，不寫死在程式裡。靜態網站在瀏覽器端讀不到環境變數，所以由建置腳本 `scripts/build.mjs` 在建置時讀取，產生 `dist/config.js` 交給網頁使用。

| 環境變數 | 說明 | 預設 |
|---|---|---|
| `NAV_DESTINATION_URL` | 目的地的 Google Maps 完整網址。建置時解析出地點名稱與座標，導航連結也由此產生。不支援 `maps.app.goo.gl` 短網址。 | 無，必填 |
| `NAV_RADIUS_KM` | 允許開始任務的範圍，單位公里，以目的地為圓心 | `5` |

- 本機：複製 `.env.example` 為 `.env` 修改，`.env` 已列入 `.gitignore`。
- GitHub：在 Settings → Secrets and variables → Actions → **Variables** 設定同名變數，改完重新執行 Deploy workflow 即生效。
- 同名的環境變數優先於 `.env`。
- 建置時會檢查：網址無法解析、找不到座標、半徑不是正數，都會直接失敗並說明原因，不會產出壞掉的網站。
- 網址資料段中最後一組 `!3d緯度!4d經度` 視為地點座標；找不到才退而使用網址裡的 `@緯度,經度`（地圖畫面中心）。

任務標題與內文目前是程式內的固定句型，以目的地名稱組成。活動期間未實作。

## 6. 檔案結構與部署

```
nav-quest/
├─ docs/plan.md            規劃文件
├─ design/                 設計稿原始檔
├─ site/                   網站原始碼
│  ├─ index.html           任務頁（所有畫面都在這一頁，以 JS 切換）
│  ├─ styles.css
│  └─ app.js               定位、狀態、畫面切換
├─ scripts/
│  ├─ build.mjs            讀環境設定、產生 dist/（含 config.js）
│  └─ serve.mjs            本機預覽用靜態伺服器
├─ .github/workflows/deploy.yml   部署到 GitHub Pages
├─ .env.example            設定範本
├─ .env                    本機設定（不進版本控制）
└─ package.json            `npm run build`、`npm run dev`
```

- 沒有第三方套件與前端框架，只需要 Node 20 以上。
- 本機預覽：`npm run dev`，開啟 `http://localhost:8080/`。localhost 視為安全來源，可以測試定位。
- 網址加上 `?reset` 會清除這支手機上的任務狀態，方便重複測試。
- 部署：推到 `main` 分支後由 GitHub Actions 建置並發佈。定位功能必須在 HTTPS 下運作，GitHub Pages 內建 HTTPS。
- QR code 的內容就是 GitHub Pages 的網址。

## 7. 隱私

- 不蒐集、不儲存、不傳送任何個人資料。GPS 座標只在使用者的手機上用來計算距離。
- 瀏覽器儲存空間只記錄任務開始與兌換的時間，資料留在使用者自己的手機上。
- 頁面上仍需說明為何要求定位，以提高同意率。

## 8. 已知限制

| 項目 | 說明 |
|---|---|
| 沒有任何數據 | 無法得知掃碼、導航、兌換的人數。 |
| 檢查可被繞過 | 範圍判斷與兌換狀態都在使用者手機上，懂技術的人可以修改。實際把關者是店員。 |
| 可重複兌換 | 清除瀏覽器資料、換瀏覽器或用無痕模式即可重來，但要回到出發地重新定位。 |
| 到店後換瀏覽器會失去任務狀態 | 例如出發地用相機掃（開 Safari），到店在其他 App 內開啟連結。此時會要求重新定位而無法通過，需由店員判斷。 |
| 連結可被轉傳 | 不在出發地的人開啟會卡在定位檢查；在出發地附近的人則可通過。 |
| 定位可能不準 | 室內或高樓間誤差較大，允許半徑要抓寬，QR code 盡量貼在靠近出入口的位置。 |
| 使用者拒絕定位 | 無法開始任務。 |

## 10. 驗收項目

1. 在出發地範圍內按「確認我的位置」並允許定位：進入任務畫面。
2. 在範圍外操作：顯示「不在範圍」，可重試。
3. 拒絕定位權限：顯示開啟權限的說明，可重試。
4. 通過定位後關閉再重新開啟任務頁：直接顯示任務畫面，不再要求定位。
5. 點「開始導航」：開啟 Google Maps，目的地為店面。
6. 到店後掃店內 QR code：顯示任務畫面與「兌換」按鈕。
7. 點「兌換」並確認：畫面變成已兌換，顯示兌換時間，時鐘持續跳動。
8. 已兌換後重新開啟任務頁：仍顯示已兌換。
9. 點「兌換」後按取消：回到任務畫面，狀態不變。
10. 無痕模式下操作：當次瀏覽可完成流程，不出現錯誤。
11. 活動期間外開啟：顯示活動未開始或已結束。
12. iPhone（Safari）與 Android（Chrome）各完成一次完整流程。

## 11. 第二階段方向（暫不規劃）

第一階段的畫面與流程都可沿用，以下功能可依需要逐項加上：

- **後端記錄**：記錄掃碼、導航點擊、兌換，取得各階段人數與轉換率。加上後，範圍判斷與兌換狀態也可移到後端，不再能被繞過。
- **身分識別與防重複兌換**：以 LINE 登入取得使用者 ID，一個帳號限兌換一次。
- **移入 LIFF**：任務頁在 LINE 內開啟，身分自動帶入。
- **LINE 官方帳號**：兌換前須加好友、圖文選單提供任務入口。
- **到店位置檢查**：兌換前確認使用者在店家附近。
